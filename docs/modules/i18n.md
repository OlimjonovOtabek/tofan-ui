# i18n (interface languages)

## Purpose

The panel speaks Uzbek (default), Russian and English. The admin switches the language in the topbar
(or on the login and status pages); every text changes without a reload and the choice survives a
refresh (`localStorage`, key `tofan.locale`). Catalog data (exercise, food and template names) is shown
in the chosen language too.

## Backend

- No endpoint. The backend ignores `Accept-Language` and always returns the three language fields
  (`name` = English, `nameUz`, `nameRu`; the same for `title*` and `body*`). Picking one is a UI job.
- Sorting by name uses the column of the current language (`name`, `name_uz`, `name_ru`); the backend
  whitelists sortable columns from the response properties, so all three are accepted.

## Structure

```text
core/i18n/
  locale.ts              AppLocale ('uz' | 'ru' | 'en'), DEFAULT_LOCALE, Intl locales, language names
  locale.store.ts        LocaleStore: locale signal, setLocale(), localStorage + <html lang>
  dictionary.ts          Dictionary (shape of the Uzbek dictionary) and TranslationKey (every leaf path)
  translate.ts           translate(locale, key, params) and translateMessage(): pure, usable in models
  translation-lookup.ts  lookupText() and interpolate() ({name} placeholders)
  translator.ts          Translator service: translate(), message(), options() for select options
  translate.pipe.ts      {{ 'media.page.title' | t }}   (typed key, impure: follows the locale)
  message.pipe.ts        {{ error | message }}          (a key or a backend text, for error messages)
  date-format.ts         formatDate / formatDateTime / formatCalendarDate (UTC dates of birth)
  page-title.ts          pageTitle(key) for route titles, translated by AppTitleStrategy
  i18n.providers.ts      provideI18n(): pushes Optimus UI texts (paginator, datepicker, ...) on change
  optimus/{uz,ru,en}.ts  Optimus UI Translation objects
  translations/{uz,ru,en}/<section>.ts   one file per feature plus common, layout, errors, enums
```

## Rules

- **UI text is never written in a template or a `.ts` file.** Add a key to
  `translations/uz/<section>.ts`, then the same key to `ru` and `en`. A missing or extra key in `ru`/`en`
  breaks the build (`Dictionary['<section>']` type), and an unknown key in `| t` or `translate()` breaks
  it too (`TranslationKey`).
- Uzbek is the source dictionary; Russian and English are written for an admin panel, not word for
  word. "Soldier" stays "Soldier" in every language.
- Labels of enum values are `Record<Value, TranslationKey>` in `models/*-labels.ts`; select options are
  `SelectOption<Value, TranslationKey>` and a component turns them into text with
  `computed(() => this.translator.options(OPTIONS))`.
- Table headers are `computed()` so they follow the locale.
- Errors: `toErrorMessage()` returns a key (known backend code or error class) or the backend text; show it
  with `| message` or `translator.message()`. A `BusinessRuleError` from a model rule carries a key.
- Toasts: `notifications.success('media.page.deleted', { name })`. Confirms take `{ key, params }`.
- Models stay free of Angular: a model that must produce text takes the `locale` and calls the pure
  `translate()` (see `features/soldiers/models/soldier-facts.ts`).
- Localized entity text is a `LocalizedText` (`shared/models/localized-text.ts`); `pickLocalized` falls
  back current language → Uzbek → English → Russian, skipping blank values.
- Dates go through `core/i18n/date-format.ts`. Uzbek stays numeric (`dateStyle: 'short'`) because
  browsers have no Uzbek month names.

## Traps

- `shared/` may import `core/i18n` (Sheriff and the table in `CLAUDE.md` allow it); `core/i18n` must
  not import features.
- Keys may contain a dotted backend code as nested objects: `errors.backend.StoredFile.InUse`.
- A pipe inside an object literal needs parentheses: `{ error: (message | message) }`.
- The `t` pipe is impure on purpose; reading the locale signal alone would not re-run a pure pipe.
- Store specs that assert toasts expect the key and params, not the text.
